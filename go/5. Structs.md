# Structs

- A `struct` is a composite data type that allows you to group related values of different data types into a single, named entity
- `structs` are value types.
- When a struct is passed to a function, a copy is made, so changes to the copy do not affect the original instance unless a pointer is used

## Comparing structs

- In the same way Go doesn't allow comparisons between variables of different primitive types, Go doesn't allow comparisons between variables that represent structs of different types.
- You can use `==` and `!=` to compare two struct variables if all of their fields are comparable
  - `slice`, `map` and `func` are non-comparable types

## Anonymous structs

- They are structs that don't have a name and, therefore, they cannot be reused

```go
car := struct {
    make string
    model string
    mileage int
}{
    make: "Toyota"
    model: "Corolla"
    mileage: 50
}

fmt.Println(car.Make)    // Access fields using dot notation
fmt.Println(car.Model)
fmt.Println(car.Mileage)
```

- Use cases:
  - Table-driven tests
  - Temporary variables
  - JSON marshalling/unmarshalling

## Struct embedding

- To embed a struct you declare a field withing another struct using only the type name. This is called an anonymous field
- It is useful to **compose types** and promote the fields and methods of the embedded struct to the outer

```go
type Employee struct {
    Name         string
    ID           string
}

func (e Employee) Description() string {
    return fmt.Sprintf("%s (%s)", e.Name, e.ID)
}

func (e Employee) PrintName() {
    fmt.Println("I'm an Employee, and my name is %s", e.Name)
}

type Manager struct {
    Employee
    Reports []Employee
}

func (e Employee) PrintName() {
    fmt.Println("I'm a Manager, and my name is %s", e.Name)
}

m := Manager{
    Employee: Employee{
        Name: "Bob Bobson",
        ID:   "12345",
    },
    Reports: []Employee{},
}
fmt.Println(m.ID)            // prints 12345
fmt.Println(m.Description()) // prints Bob Bobson (12345)
```

- If the outer struct defines a field or method with the same name as one in the embedded struct, the outer struct's version "shadows" (takes precedence over) the embedded one.
- You can still access the shadowed field/method using the embedded type name

```go
m.PrintName()           // Prints: I'm a Manager, and my name is...
m.Employee.PrintName()  // Prints: I'm an Employee, and my name is...
```

- Embedding is not **inheritance**. It is essentially syntactic sugar for **composition**.
- In the example above, you cannot assign a variable of type `Manager` to a variable of type `Employee`, for instance
