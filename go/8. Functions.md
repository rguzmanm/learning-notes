# Functions

- Functions can be defined inside any block
- Functions in Go don't have named and optional input parameters
  - To simulate them, use a `struct`

```go
type MyFuncOpts struct {
    FirstName string
    LastName  string
    Age       int
}

func MyFunc(opts MyFuncOpts) error {
    // do something here
}

func main() {
    MyFunc(MyFuncOpts{
        LastName: "Patel",
        Age:      50,
    })
    MyFunc(MyFuncOpts{
        FirstName: "Joe",
        LastName:  "Smith",
    })
}
```

- Go allows for multiple return values
- Functions **are values**
  - The type of a function is built out of its _signature_
  - You can declare function variables and assigned to any function with the same signature

```go
var myFuncVariable func(string) int

func f1(a string) int {
    return len(a)
}

func main() {
    var myFuncVariable func(string) int
    myFuncVariable = f1
    result := myFuncVariable("Hello")
    fmt.Println(result) // Prints 5
}
```

- You can pass functions as arguments to other functions
- Functions can be returned from functions

## Anonymous functions

- They are functions defined without a name
- They can be used:
  - To create _Immediately Invoked Function Expressions (IIFE)_
  - To be assigned to a variable
  - To be passed as an argument
- Only `anonymous functions` can be declared within another function

## Closures

- Functions declared inside functions are able to _access_ and _modify_ variables declared in the outer function¨

```go
func main() {
    a := 20
    f := func() {
        fmt.Println(a) // Prints 20
        a = 30
    }
    f()
    fmt.Println(a) // Prints 30
}
```

- `closures` allow you to limit a function's scope. If a function is going to be called from only one other function, but it's called multiple times, you can use an inner function to _hide_ the called function
- It makes sense to use a `closure` when the inner function:
  - Is not reusable
  - Is not testable independently
  - Is tightly tied to implementation details (needs access to outer variables)

### Use cases

- Build a `middleware` for a web server
- Resource cleanup via the `defer` keyword

```go
func main() {
    f, closer, err := getFile(os.Args[1])
    if err != nil {
        log.Fatal(err)
    }
    defer closer()
}

func getFile(name string) (*os.File, func(), error) {
    file, err := os.Open(name)
    if err != nil {
        return nil, nil, err
    }
    return file, func() {
        file.Close()
    }, nil
}
```

- You can defer multiple functions in a Go function.
- They run in last-in, first-out (LIFO) order; the last defer registered runs first.
- The code within `defer` functions runs after the return statement.
- The input parameters are evaluated immediately and their values are stored until the function runs.

## Go is Call by Value

- When supplying a variable for a parameter to a function, Go _always_ makes a copy of the value of the variable
- `maps` and `slices` can be modified when passed to functions because their values contain a **pointer to an underlying shared data structure**
  - For `slices` if you append elements and the current capacity is exceeded, Go allocates a new backing array. Therefore, the original slice remains linked to the old array and the changes in length and capacity will not be reflected.
