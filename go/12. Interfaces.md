# Interfaces

- An `interface` is a collection of method signatures that defines the behavior of a type.
- Any concrete type (like a struct) that implements all the methods specified in an interface **implicitly** satisfies that interface, without an explicit declaration like an `implements` keyword.

- You can embed interfaces:

```go
type Reader interface {
        Read(p []byte) (n int, err error)
}

type Closer interface {
        Close() error
}

type ReadCloser interface {
        Reader
        Closer
}
```

- Just as you can embed a concrete type in a `struct`, you can also embed an `interface` in a `struct`

## Accept interfaces, return structs

- It is a design principle that promotes flexible, decoupled inputs and extensible, transparent outputs.
- Why accept `interfaces`?
  - **Loose coupling:** The calling code is not bound to a specific implementation
  - **Clearer dependencies:** The function's signature explicitly documents the _behavior_ it requires from its inputs, rather than the full capabilities of a concrete type (struct)
- Why return `structs`?
  - **Extensibility without breaking changes:** You can add new methods or fields to a struct without breaking existing code that uses it.
  - **Simplicity and predictability:** Returning a concrete type makes it clear to the user what they are getting and how it behaves

## Nil interfaces

- In the Go runtime, interfaces are implemented as a struct with two pointer fields, one for the **value** and one for the **type** of the value. As long as the type field is non-nil, the interface is non-nil.

```go
var s fmt.Stringer      // Stringer (nil, nil)      --> Both, the type and the value are nil
fmt.Println(s == nil)   // prints true

var p *Person            // nil of type *Person
var s1 fmt.Stringer = p  // Stringer (*Person, nil) --> Only the value is nil
fmt.Println(s1 == nil)   // prints false
```

## Comparing interfaces

- Two interfaces are equal only if **types** are equal, and **values** are equal
- If the values of the interface are not comparable (like a slice, for instance) a runtime panic will occur if you try to compare them.

## The Empty interface

- Go uses an empty interface, `interface{}`, to represent a variable that could store a value of any type.

```go
var i interface{}
i = 20
i = "hello"
i = struct {
    FirstName string
    LastName string
} {"Fred", "Fredson"}
```

- An empty interface type simply states that the variable can store any value whose type implements zero or more methods. This just happens to match every type in Go.
- To improve readability, Go added `any` as a type alias for `interface{}` (after version 1.18)

## Type assertions and type switches

- They are used to extract an **interface** value's underlying concrete value and check if it matches a specific type.
- Type assertions can be applied only to interface types.
- The syntax for a type assertion is `i.(T)`, where `i` is an interface variable and T` is the type you want to assert

```go
var i interface{} = "hello"
s := i.(string) // s is a string, value is "hello"
```

- It is recommended to **always** use the comma-ok idiom to avoid a panic at runtime (even if you are absolutely certain that your type assertion is valid)

```go
var i interface{} = 42

if s, ok := i.(string); ok {
    fmt.Println("String value:", s)
} else {
    fmt.Println("Not a string") // This path is taken
}
```

- When an interface could be one of multiple possible types, use a _type switch_ instead

```go
func doThings(i any) {
    switch j := i.(type) {
    case nil:
        // i is nil, type of j is any
    case int:
        // j is of type int
    case bool, rune:
        // i is either a bool or rune, so j is of type any
    default:
        // no idea what i is, so j is of type any
    }
}
```

- The type of the new variable depends on which case matches:
  - You can use `nil` for one case to see if the interface has no associated type.
  - If you list more than one type on a case, the new variable is of type `any`.
  - You can have a default case that matches when no specified type does.
  - Otherwise, the new variable has the type of the case that matches.
- It is idiomatic to assign the variable being switched on to a variable of the same name (`i := i.(type)`), making this one of the few places where shadowing is a good idea.
- One common use case is the **optional interface** pattern: Accept a general interface, but check if the value also implements a more specific interface.This allows extra behavior without requiring it.

```go
func Process(r Reader) {
	fmt.Println(r.Read())

	// Check if it also implements Closer
	if c, ok := r.(Closer); ok {
		c.Close()
	}
}
```
