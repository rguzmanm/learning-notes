# Nominal typing

It means that types are compatible **only if they explicitly declare that they are related.**
The **name of the type matters:** Two types that look identical are still different unless the language says they are related. Take for instance this Java code:

```java
class Dog {
    void bark() {}
}

class Cat {
    void bark() {}
}
```

Even though both have the method `bark` you **cannot** treat `Cat` as `Dog` because they have different names.
If you want compatibility, you must explicitly declare it:

```java
interface Barker {
    void bark();
}

class Dog implements Barker {}
class Cat implements Barker {}
```

# Structural typing

It means that types are compatible if their **structure matches**.
The **shape of the type matters:** If two types have the same fileds or methods, they are compatible. Take for instance this TypeScript code:

```typescript
type Dog = {
  name: string;
};

type Cat = {
  name: string;
};

let dog: Dog = { name: "Fido" };
let cat: Cat = dog;
```

This works because both have the same structure `{name: string}`. The name `Dog` and `Cat` are irrelevant.

Structural typing occurs at **compile time** and checks if the **entire** shape (structure) matches

# Duck typing

It is the **dynamic** version of structural typing.
If an object has the required behavior at **runtime**, it's accepted: It doesn't care about type definitions, only behavior at runtime. For instance:

```python
class Dog:
    def speak(self):
        print("Woof")

class Robot:
    def speak(self):
        print("Beep")

def make_speak(obj):
    obj.speak()

make_speak(Dog())
make_speak(Robot())
```

`make_speak(Dog())` and `make_speak(Robot())` work because they both have: `speak()`.

Structural typing checks if the entire shape matches, whereas duck typing only checks the specific methods/properties being accessed.
