# Maps

- It's a buit-in, unordered data structure that stores data as a collection of unique **key-value pairs**
- You can declare maps:
  - Using a literal: `map[K]V{ ... }`
  - Using make: `make(map[K]V)` or `make(map[K]V, capacityHint)`
  - Nil map: `var m map[K]V`
- When declaring a map with `make`, the capacity hint is just an approximation of how many elements you expect to store. It does not fix the size, limit the map, nor set an accesible capacity. It only helps the runtime preallocate internal buckets
- A `nil map` is different from an `empty map` (for both `len=0`, but only `nil` compares to `nil` )
- Similarly to slice, `maps`:
  - Automatically grow as you add key-value pairs to them
  - The zero value for a map is `nil`
  - Maps are not comparable. You can check if they are equal to `nil`, but you cannot check if two maps have identical keys and values using `==` or differ using `!=`
  - To compare is two maps are equal use `maps.Equal`
- The key for a `map` can be any comparable type. This mean you _cannot_ use a `slice`, `map` or a `func` as the key for a map.
- The `map` in Go is a `hash map`
- When you retrieve a value from a map, **you get a copy**, not a **reference** to the original stored inside the map

## Iterating a map

- Go allows you to **modify a `map` during iteration**, which most other languages don't.
- As a security feature, when iterating a map, the order of the keys and values may vary

```go
m := map[string]int{
   "a": 1,
   "c": 3,
   "b": 2,
}

for i := 0; i < 3; i++ {
    fmt.Println("Loop", i)
    for k, v := range m {
        fmt.Println(k, v)
    }
}

// Loop 0
// c 3
// b 2
// a 1
// Loop 1
// a 1
// c 3
// b 2
// Loop 2
// b 2
// a 1
// c 3
```

## The coma ok idiom

- A `map` return the zero value if you ask for the value associated with a key that's not in the map.
- Go provides the _comma ok idiom_ to tell the difference between a key that's associated with a zero value and a key that's not in the map:

```go
m := map[string]int{
   "hello": 5,
   "world": 0,
}
v, ok := m["hello"]
fmt.Println(v, ok) // Prints 5 true

v, ok = m["world"]
fmt.Println(v, ok) // Prints 0 true

v, ok = m["goodbye"]
fmt.Println(v, ok) // Prints 0 false
```

## Using Maps as Sets

- Go doesn’t include a set, but you can use a map to simulate some of its features.
- Use the key of the map for the type that you want to put into the set and use a `bool` for the value.
  - The main advantage of using `bool` is readability
  - The disadvantage is that `bool` values can use 1 byte

```go
intSet := map[int]bool{}
vals := []int{5, 10, 2, 5, 8, 7, 3, 2, 10}
for _, v := range vals {
    intSet[v] = true
}
```

- Another option is to use `struct{}` for the value instead of `bool`.
  - The advantages of using `struct{}` is that empty structs uses zero bytes and the intent of using a map as a set is clearer
  - The disadvantage is that it makes your code clumsier, since you need a the _comma ok_ idiom to checks if a value is in the set

```go
intSet := map[int]struct{}{}
vals := []int{5, 10, 2, 5, 8, 7, 3, 2, 10}
for _, v := range vals {
    intSet[v] = struct{}{}
}
if _,ok := intSet[5]; ok {
    fmt.Println("5 is in the set")
}
```

- For more complex operations like union, intersection, etc., use third-party libraries.
